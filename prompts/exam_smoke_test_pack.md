# Zora Lite Exam Smoke Test Pack

Use this pack to test the app against real-style prompts instead of relying only on review feedback.

This pack now covers:
- `2 Marks`
- `5 Marks`
- `10 Marks`
- `Assignment`
- `Report`
- `Research`

How to use:
1. Run the backend and frontend.
2. Select the required mode or task in the app.
3. Paste the exact test question from this file.
4. Compare the output against the checklist.
5. Record what is missing, too generic, repeated, or inaccurate.

---

## A. Notes Mode Tests

### Test A1: 2 Marks

Suggested mode: `2 Marks`

Question:

```text
What is machine learning?
```

What a strong answer should include:

- One clear definition.
- Two to four short supporting points.
- Very little filler.
- No long explanation or unnecessary sections.
- Around short exam-note length.

Common weak-output signs:

- Answer is too long for 2 marks.
- Too many headings.
- Too generic or conversational.

---

### Test A2: 5 Marks

Suggested mode: `5 Marks`

Question:

```text
Explain the advantages and limitations of cloud computing.
```

What a strong answer should include:

- Brief introduction or definition.
- Clear explanation of advantages.
- Clear explanation of limitations.
- Balanced structure.
- Short conclusion.
- Better depth than 2 marks, but not as long as a 10-mark answer.

Common weak-output signs:

- Only bullet points without explanation.
- Too short and looks like a 2-mark answer.
- Too long and overly detailed for 5 marks.

---

### Test A3: 10 Marks

Suggested mode: `10 Marks`

Question:

```text
Explain the resource allocation difficulties, critical path, and scheduling in project management.
```

What a strong answer should include:

- Resource allocation difficulties should mention limited resources, uncertainty in activity duration, skill mismatch, task dependency conflicts, and overallocation or underutilization.
- Critical path should explicitly mention the longest path in the project network.
- Critical path should mention minimum project completion time.
- Critical path should mention zero slack or float for critical activities.
- Scheduling should mention sequence of activities.
- Scheduling should mention start and finish times.
- Scheduling should ideally mention Gantt chart, PERT, or CPM.
- The answer should handle all three parts in separate clear sections.
- The answer should feel complete enough for a full 10-mark response.

Common weak-output signs:

- Only short definitions with no depth.
- Critical path explained without `longest path` or `zero slack`.
- Scheduling explained generally without time planning tools.
- Looks like a 5-mark answer.

---

### Test A4: 10 Marks

Suggested mode: `10 Marks`

Question:

```text
What is machine learning? Explain its types, working process, applications, advantages, and limitations.
```

What a strong answer should include:

- A clear definition of machine learning.
- Relation to artificial intelligence if relevant.
- Types: supervised learning, unsupervised learning, and reinforcement learning.
- Working process: data collection, preprocessing, training, testing, evaluation, and prediction or deployment.
- Real academic applications.
- Advantages such as automation, pattern detection, prediction, and scalability.
- Limitations such as data dependency, bias, overfitting, interpretability issues, and computational cost.
- A solid conclusion.

Common weak-output signs:

- Only definition plus examples.
- No workflow or no types.
- Too generic for 10 marks.

---

### Test A5: 10 Marks

Suggested mode: `10 Marks`

Question:

```text
Explain process scheduling in operating systems. Discuss its objectives and compare preemptive and non-preemptive scheduling.
```

What a strong answer should include:

- A definition of process scheduling.
- The role of CPU scheduling and ready queue.
- Objectives such as CPU utilization, throughput, turnaround time, waiting time, and response time.
- A clear explanation of preemptive scheduling.
- A clear explanation of non-preemptive scheduling.
- A comparison table or clearly separated comparison points.
- Standard examples such as Round Robin, SJF, FCFS, or Priority Scheduling.
- A proper conclusion.

Common weak-output signs:

- Talks about scheduling only in generic terms.
- No distinction between objectives and scheduling types.
- Comparison is too short or missing examples.

## B. Assignment Mode Tests

### Test B1: Assignment

Suggested task: `Assignment`

Question:

```text
Write an assignment on the role of artificial intelligence in education.
```

What a strong answer should include:

- A meaningful title.
- Formal academic tone.
- Clear introduction.
- Main body with section headings.
- Explanation of benefits, applications, challenges, and future scope.
- A proper conclusion.
- Assignment-like flow rather than short notes.

Common weak-output signs:

- Reads like exam notes instead of an assignment.
- No headings.
- Too short and underdeveloped.
- Informal tone.

- Types or methods such as unit, integration, system, and acceptance testing.

## E. Quick Scoring Rubric

Use this simple rubric after each output:

- `9-10/10`: Complete, precise, well-structured, task-appropriate, low filler.
- `7-8/10`: Mostly correct, but missing some depth, structure, or key terms.
- `5-6/10`: Understandable but generic, short, or incomplete.
- `Below 5/10`: Major missing sections, wrong task style, weak structure, or inaccuracies.

## F. What To Record

For each test, note:

- Missing keywords
- Missing sections
- Wrong tone for the selected task
- Overly generic lines
- Wrong or non-standard terminology
- Repetition
- Whether the answer length matches the selected mode
- Whether the structure matches the selected task

Simple recording format:

```text
Test:
Mode/Task:
Score:
Worked well:
Missing:
Too generic:
Next fix:
```
